# トレカ買取マップ（Webアプリ）

ONE PIECEカードゲームの買取金額をまとめて比較・地図表示するWebアプリです。
React + TypeScript + Vite で構築しています。

## セットアップ

```bash
cd web
npm install
npm run dev
```

`http://localhost:5173` を開くと確認できます。

## デモを見る（iPhoneなどスマートフォンから）

ビルド済みの静的ファイルを `gh-pages` ブランチにプッシュ済みです。あとはリポジトリのオーナーが
一度だけ次の設定をすれば、公開URLが発行されスマートフォンのブラウザからそのまま開けるようになります。

1. GitHubでこのリポジトリの **Settings → Pages** を開く
   （`https://github.com/gnmnmd-code/-/settings/pages`）
2. 「Build and deployment」の **Source** を「Deploy from a branch」に設定
3. **Branch** を `gh-pages` / `/ (root)` に設定して **Save**
4. 数十秒〜数分で **https://gnmnmd-code.github.io/-/** が公開される

公開後はiPhoneのSafariで上記URLを開くだけで確認できます。共有ボタン→「ホーム画面に追加」をすると、
アプリのようにアイコンから起動できます。以降 `web/` を更新して `gh-pages` ブランチに再デプロイすれば、
同じURLに最新版が反映されます（再デプロイの手順は次回このURLの内容を差し替える形で対応します）。

## 実装済み機能

1. **データ構造とサンプルデータ**
   - `src/types.ts`: `Card` / `Shop` / `PriceData` / `ExtractedPriceData` の型定義
     （`Card` は `game` を持つが、現在はONE PIECEカードゲームのみを扱う。`Shop` は `prefecture` で都道府県を保持）
   - `src/data/mockData.ts`: ONE PIECEカードゲームの実在のカード名・型番・レアリティを反映したサンプル35種
     - ルフィ／ベタベットン流星／シャンクス／カイドウ／トラファルガー・ロー／コアラ／ユースタス・キッド／サボ
       は「カードラッシュ秋葉原0号店」(shop-g)の公式買取価格ページ（cardrush.media）から実データを取得
     - ボルサリーノ／マーシャル・Ｄ・ティーチ／ロロノア・ゾロ／ポートガス・D・エース／ゲッコー・モリア／
       リーダー版ルフィ(ST01-001)／クロコダイル／トニートニー・チョッパー／ゴール・D・ロジャー／ナミ／
       光月おでん等26種は、実店舗「アキバカードショップ メルカード」(shop-h)の公式買取価格表ページ
       （https://akihabara-cardshop.com/onepice-kaitori/）からカード名・型番・レアリティ・価格・商品画像を
       そのまま取得（同ページは約2,866件の買取価格データを持つ）
     - エドワード・ニューゲート／ウソップ／ニコ・ロビン／ヤマト／シャーロット・リンリン／
       ロックス・Ｄ・ジーベック／ロキ／カイドウ(OP17-062)／シキ／クイーン／ヤソップ／ゾロ(OP17-095) の
       12種は、**ONE PIECEカードゲーム公式サイトのカードリストページ**
       （https://www.onepiece-cardgame.com/cardlist/?series=550117＝ブースターパック
       世界最強の戦士【OP-17】）からカード名・型番・レアリティ・公式画像を取得し、価格はメルカードの
       実データと突き合わせたもの。このページはブラウザ相当のUser-Agentを付けたHTTPクライアントで
       正常に取得でき、カード名・型番・レアリティ・公式カード画像URLがHTMLに直接埋め込まれていた
     - 上記いずれの実店舗データも無いカードは、他店相場調査を参考にした演出用ダミー値
       （`PriceData.sourceUrl` を持たない＝実データではないことを示す）
     - シャンクス(OP09-001)の商品画像は、買取価格(¥10,000)と同じillust:otton版の実画像を使用
       （同型番・同レアリティでもillust:DAI-XT.版は¥100と大きく異なるため、画像と価格の対応を揃える必要が
       あった。トラファルガー・ロー等、パラレル版で価格が跳ね上がるカードは`printNote`に注記している）

2. **価格比較画面**（`/` = `src/pages/CardListPage.tsx`）
   - カード名・型番での検索、都道府県での絞り込み（選択中の都道府県はURLクエリ `?prefecture=` に保持）
   - **買取金額（最高額）が高い順に降順で表示**（都道府県を絞ると、その範囲内の最高額で再計算・再ソート）
   - 店舗ごとの買取価格一覧、最高額バッジ
   - 最高額と最安額の「最大差額」を赤字で表示
   - 行タップでカード詳細画面へ遷移（`react-router-dom` によるページ遷移。絞り込み中の都道府県も引き継ぐ）

3. **店舗マップ画面**（`/map` = `src/pages/ShopMapPage.tsx`）
   - `react-leaflet` + OpenStreetMapタイルで店舗の地図を表示
   - カード・都道府県をプルダウンで切り替えると、ピン・買取価格が連動して切り替わる
     （最高額店舗のピンは色分け。地図の表示範囲も選択に応じて自動でフィット）
   - ピンタップで店舗名・都道府県・営業時間・買取価格をポップアップ表示
   - 「マップアプリでルート案内を開く」ボタンでGoogleマップの経路案内を新規タブで開く
     （スマートフォンではOS標準のマップアプリ選択に誘導されます）

4. **買取表画像のAI解析（受け皿）**（`src/services/imageParserService.ts`、デモ画面 `/ai-demo`）
   - `parseImage(image: File | Blob): Promise<ExtractedPriceData[]>` を定義
   - 現段階では実際のVision LLM APIを呼ばず、2秒後にダミー結果を返すモック実装
   - 将来的に `fetch` で OpenAI API 等の画像解析エンドポイントに差し替える想定（TODOコメントに記載）

5. **カード画像・公式サイトへの導線・更新日の表示**
   - 一覧・詳細・地図ポップアップの全画面でカード画像を表示（`Card.imageUrl`）。カードラッシュ／ドラゴンスターの
     商品ページに掲載されている実画像を参照している（ホットリンク。本番では利用規約を確認のうえ、
     許諾を得た画像を自社配信することを推奨）
   - 同じ型番でもパラレル・SP・イラスト違いで価格が大きく変わるため、`PriceData.printNote` に注記を持たせられる
     ようにした（例: シャンクスのillust:otton版とillust:DAI-XT.版で¥10,000と¥100の差）
   - 各価格の横に「更新日」を表示（`formatUpdatedAt`）
   - 実データが確認できた価格には「公式サイトはこちら」リンクを表示し、掲載元ページ（`PriceData.sourceUrl`）
     または店舗の公式サイト（`Shop.websiteUrl`）に遷移できるようにした。架空のデモ店舗にはリンクを出さず、
     実店舗と演出用データが一目で区別できるようにしている
   - 全画面に「価格は目安です。最終判断は各店舗の公式サイトでご確認ください」という注意書きを常時表示

6. **メルカリへの導線**（`src/config/mercari.ts`）
   - 各カードに「メルカリの相場を見る」リンクを設置（一覧の各行・詳細画面）。`mercariSearchUrl()` が
     カード名+型番でのメルカリ検索結果ページURLを組み立てる
   - メルカリは利用規約上スクレイピングでの相場取得はリスクが高く、公開APIも自社ショップ管理用の
     「メルカリShops API」のみで他者の出品検索には使えないため、今回は組み込んでいない
   - アフィリエイト（提携ASP「アクセストレード」経由）は提携審査が必要で、この場ではアカウント登録・審査を
     代行できないため、現状は素の検索リンクのみ。審査が通りアフィリエイトIDを取得したら、
     `mercariSearchUrl()` の中身を1箇所差し替えるだけでトラッキングリンクに移行できる設計にしている

- React 19 + TypeScript
- Vite
- react-router-dom（画面遷移）

## 今後のロードマップ（未実装／要検討）

実際にサービスとして成立させるには、以下の要素が別途必要です。

### 1. カードマスタの正式データ化
- ONE PIECEカードゲーム公式サイト（onepiece-cardgame.com/cardlist）は、ブラウザ相当のUser-Agentを
  付けたHTTPクライアント（`curl -A "Mozilla/5.0..."`）で取得すると、カード名・型番・レアリティ・
  公式カード画像URLがHTMLに直接埋め込まれていることを確認済み（`?series=<シリーズID>` でパックごとに
  絞り込める）。当初はJS描画だと思い込んでいたが、実際にはサーバー側でレンダリングされていた
- シリーズIDと収録パックの対応は現状手作業で特定している。全パック分を網羅するには、
  シリーズID一覧を取得する方法（サイト内のセレクトボックスの値を総当たりする等）を別途調べる必要がある
- 買取価格は公式サイトには無いため、引き続きカードショップ（カードラッシュ・メルカード等）の
  買取価格ページと突き合わせる運用になる
- 取得したマスタは `mockData.ts` の `cards` 配列と同じ形（id / game / cardName / modelNumber / rarity /
  imageUrl）に変換してDBへ投入する想定

### 2. データ収集の自動化
- **カードショップの公式サイト（買取ページ）からの収集**: 動作確認済み
  - 遊々亭のようなサイトはHTMLがそのまま取得できたが、カードラッシュ（cardrush.media）は
    一般的なfetchツールに対してBot対策と思われる403を返した。ブラウザ相当のUser-Agentを付けた
    `curl`ではHTTP 200で取得できたため、実運用でもブラウザヘッダーを模したHTTPクライアント
    （またはヘッドレスブラウザ）でのアクセスが必要になる可能性が高い
  - サイトごとにHTML構造が異なるため、店舗ごとに抽出ロジック（パーサー）が必要
  - 利用規約・robots.txtの確認と、節度あるアクセス頻度（例: 1日1回のバッチ）を徹底する
- **X（旧Twitter）検索結果から買取表画像を収集する仕組み**
  - X API（有料プラン）でのツイート検索、もしくは手動でのスクリーンショット取り込み
  - X APIの利用規約・レートリミットの確認が必須
- `ImageParserService` を実際のVision LLM API（OpenAI GPT-4o Vision、Claude等）に接続
  - 抽出精度の検証、誤認識時の手動修正UI
  - 抽出したカード名・型番は上記「1. カードマスタ」と突き合わせて正規化する

### 3. バックエンド・永続化
- 現状は全データがフロントエンドのモック配列（メモリ内）
- カード・店舗・価格データを保存するAPI/DB（例: Supabase, Firebase, 自前API + PostgreSQL）
- 価格データの更新日時管理・重複排除・信頼性スコアリング（同じ店舗の価格が乱立した場合の名寄せ）

### 4. 店舗データの拡充
- 現在は東京・大阪・愛知のサンプル5店舗のみ。都道府県フィルタのUIは実装済みなので、
  店舗データを増やすだけで全国対応が可能
- 住所→緯度経度のジオコーディング（Google Geocoding API等）を組み込んだ店舗登録フロー
- 店舗の営業時間・電話番号等を店舗側が自己申告 or 公開情報から収集する仕組み

### 5. ユーザー機能
- カードのお気に入り登録・価格変動通知（プッシュ通知 or メール）
- ユーザー投稿による価格情報の補完（信頼度に応じた表示）

### 6. 非機能面
- 著作権・商標（カード画像、店舗名の扱い）への配慮
- 利用規約・免責事項（買取価格は変動する旨の明記）
- 本番デプロイ（Vercel / Netlify 等）とドメイン取得
- アクセス解析・エラーモニタリング

まずは今回作成したモックデータ版で画面遷移・UXを固めた上で、
「3. バックエンド・永続化」→「2. データ収集の自動化」の順に着手するのがおすすめです。
