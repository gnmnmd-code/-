# トレカ買取マップ（Webアプリ）

ONE PIECEカードゲームの買取金額をまとめて比較・地図表示するWebアプリです。
React + TypeScript + Vite で構築しています。

## セットアップ

```bash
cd web
npm install
npm run dev
```

`http://localhost:5173` を開くと確認できます。

## デモを見る（iPhoneなどスマートフォンから）

ビルド済みの静的ファイルを `gh-pages` ブランチにプッシュ済みです。あとはリポジトリのオーナーが
一度だけ次の設定をすれば、公開URLが発行されスマートフォンのブラウザからそのまま開けるようになります。

1. GitHubでこのリポジトリの **Settings → Pages** を開く
   （`https://github.com/gnmnmd-code/-/settings/pages`）
2. 「Build and deployment」の **Source** を「Deploy from a branch」に設定
3. **Branch** を `gh-pages` / `/ (root)` に設定して **Save**
4. 数十秒〜数分で **https://gnmnmd-code.github.io/-/** が公開される

公開後はiPhoneのSafariで上記URLを開くだけで確認できます。共有ボタン→「ホーム画面に追加」をすると、
アプリのようにアイコンから起動できます。以降 `web/` を更新して `gh-pages` ブランチに再デプロイすれば、
同じURLに最新版が反映されます（再デプロイの手順は次回このURLの内容を差し替える形で対応します）。

## 実装済み機能

1. **データ構造とサンプルデータ（3,134種、自動生成パイプライン付き。2店舗の買取価格を突き合わせ）**
   - `src/types.ts`: `Card` / `Shop` / `PriceData` / `ExtractedPriceData` の型定義
     （`Card` は `game` を持つが、現在はONE PIECEカードゲームのみを扱う。`Shop` は `prefecture` で都道府県を保持。
     `Card.variantLabel` にパラレル版・SP版・プロモ再録版などの注記を保持する）
   - `src/data/mockData.ts` は2種類のデータで構成される:
     - **手入力データ（8種）**: ルフィ・シャンクス・ベタベットン流星のように、複数店舗の比較デモや、
       パラレル版で価格が跳ね上がる例（`printNote`）など、自動生成だけでは表現できない情報を持つカード
     - **自動生成データ（3,129種、うちパラレル/SP等の印刷違いが2,517種）**: `scripts/fetch-onepiece-cards.mjs` が
       生成する `src/data/onepiece-cards.generated.json`（カードマスタ）と
       `src/data/onepiece-prices.generated.json`（店舗別価格。1カードにつき0〜複数件）を読み込んだもの。
       以下を型番で突き合わせている
       1. **ONE PIECEカードゲーム公式サイトのカードリスト**（onepiece-cardgame.com/cardlist）
          全62シリーズ（ブースター・スタートデッキ・プロモーションカード等すべて）を走査し、
          カード名・型番・レアリティ・公式カード画像URLと、収録パック/デッキの正式名称を取得
          （公式カード総数2,823種、収録パック/デッキ59種）。パック名は
          `src/data/onepiece-sets.generated.json` に出力される
       2. **実店舗「アキバカードショップ メルカード」の買取価格表**（shop-h）
          （https://akihabara-cardshop.com/onepice-kaitori/）から型番・買取価格・商品画像を取得
          （全2,864件）。「型番」欄はパラレル版などの印刷違いを「パラレル版OP05-118」
          「パラレル加工版OP05-118『PRB01』」のように、基本型番の前後に説明文を付けて表す
       3. **カードショップ 遊々亭の買取価格表**（shop-i）
          （https://yuyu-tei.jp/buy/opc/s/&lt;セットコード&gt;。全59セットを走査）から
          型番・買取価格・商品画像を取得。「カード名」欄末尾の括弧書き（例:
          「ロックス・D・ジーベック(パラレル)(海賊団スーパーパラレル)」）が印刷違いの注記にあたる。
          **注意**: 遊々亭は「/buy/」（お店が買う＝買取。今回使用）と「/sell/」（お店が売る＝通販の
          販売価格）で別々にページが分かれており、両ページとも見た目のURLが紛らわしい
          （`/buy/`が買取、`/sell/`が販売、と実際のURLは逆の語感になる点に注意）。開発当初は誤って
          `/sell/`（販売価格）の方を取得してしまい、買取アプリなのに販売価格が混ざっていたため、
          `/buy/`側に修正した経緯がある。各ページの`og:description`に「カード買取ページです」
          「シングルカード販売ページです」と明記されているので、迷ったら実際にそのメタデータで確認するのが確実
       - パラレル版等の注記が無い「通常版」は**型番だけで店舗横断に同一カードとして突き合わせる**ため、
         メルカード・遊々亭の両方に買取価格があるカードは、1枚のカードとして2店舗の価格を比較できる
         （現状271種）。一方パラレル版等（注記あり）は、店舗ごとに表記の書式が違うため誤って別の印刷を
         同一視するリスクがあり、店舗ごとに別カードのまま保持する（店舗をまたいだ比較はできないが、
         安全側に倒している）
       - 公式データが無い、または買取価格が無いカードは対象外（価格の無いカードは比較のしようがないため）
   - **パラレル/SP版の見分け方**: 一覧・詳細・店舗別カード一覧のいずれの画面でも、型番・レアリティの
     横にオレンジ色のバッジで `variantLabel`（例:「パラレル版」「パラレル・海賊団スーパーパラレル」）を表示する。
     カード名・型番検索は `variantLabel` の文字列にもマッチするため、「パラレル」等で検索すれば絞り込める
   - **パック/デッキでの絞り込み**: 型番の頭（`OP17` `ST23` 等）から収録パックを判定する
     `setCodeForModel()` と、その表示名を返す `setLabel()` を用意。価格比較画面の絞り込みプルダウンで使用
   - **さらにカードを増やすには**: `npm run fetch:cards`（内部で
     `node scripts/fetch-onepiece-cards.mjs` を実行）で再取得・再生成できる。増やすには他の実店舗の
     買取価格ページを追加で取り込んで突き合わせ対象を増やす必要がある
     （詳細はロードマップ「1. カードマスタの正式データ化」参照）
   - **データの自動更新**: 1日2回（JST 8:00・20:00）、Claude Code RemoteのRoutine機能でこのスクリプトを
     自動実行し、差分があればコミット・`gh-pages`への再デプロイまで行うよう設定済み
     （詳細はロードマップ「2. データ収集の自動化」参照）

2. **価格比較画面**（`/` = `src/pages/CardListPage.tsx`）
   - カード名・型番での検索
   - **収録パック/スタートデッキでの絞り込み**（例: 「OP17: ブースターパック 世界最強の戦士」
     「ST23: スタートデッキ 赤 シャンクス」）。型番のハイフンより前の部分（OP〇〇=ブースターパック、
     ST〇〇=スタートデッキ、EB〇〇=エクストラブースター、PRB〇〇=プレミアムブースター、
     P=プロモーションカード）から自動判定している（`setCodeForModel()`）。選択肢はカードが実在するパック/
     デッキのみを表示
   - 都道府県での絞り込み（選択中の条件はURLクエリ `?set=` `?prefecture=` に保持）
   - **買取価格帯での絞り込み**（例:「〜999円」「100,000円〜」。`src/config/display.ts` の
     `PRICE_SEGMENTS` で定義。選択中の条件はURLクエリ `?price=` に保持）
   - **買取金額（最高額）が高い順に降順で表示**（絞り込むと、その範囲内の最高額で再計算・再ソート）
   - **表示形式の切り替え（リスト/4列グリッド）**: 「リスト」は従来通り店舗ごとの買取価格・最大差額まで
     表示する詳細表示、「4列」はカード画像・カード名・最高額のみのグリッド表示で、カードが多くても
     スクロール量を抑えて一覧できる。選んだ表示形式は端末に保存され、次回訪問時も引き継がれる
     （`src/config/display.ts` の `loadViewMode()` / `saveViewMode()`）
   - 店舗ごとの買取価格一覧、最高額バッジ（リスト表示時）
   - 最高額と最安額の「最大差額」を赤字で表示（リスト表示時）
   - タップでカード詳細画面へ遷移（`react-router-dom` によるページ遷移。絞り込み中の都道府県も引き継ぐ）

3. **店舗一覧画面**（`/shops` = `src/pages/ShopListPage.tsx`）
   - ナビゲーションの「店舗一覧」から入る、店舗起点のメイン画面（買取カード枚数が多い順に表示）
   - 都道府県での絞り込み
   - 店舗をタップすると店舗詳細画面（`/shop/:shopId` = `src/pages/ShopDetailPage.tsx`）へ遷移し、
     その店舗が買取しているカードを**価格が高い順**に一覧表示（カード名・型番・価格帯で絞り込み可能）
   - 店舗詳細画面にも価格比較画面と同じ**リスト/4列グリッドの表示形式切り替え**を設置
   - 店舗詳細画面には「ルート案内を開く」（Googleマップの経路案内を新規タブで開く）と
     「公式サイトはこちら」のボタンを設置

4. **カード別の店舗地図**（`/map` = `src/pages/ShopMapPage.tsx`）
   - カード詳細画面の「この価格で店舗を地図で見る」から遷移する補助画面
   - `react-leaflet` + OpenStreetMapタイルで、選んだカードを買取している店舗を地図上に表示
   - カード・都道府県をプルダウンで切り替えると、ピン・買取価格が連動して切り替わる
     （最高額店舗のピンは色分け。地図の表示範囲も選択に応じて自動でフィット）
   - ピンタップで店舗名・都道府県・営業時間・買取価格をポップアップ表示

4. **買取表画像のAI解析（受け皿）**（`src/services/imageParserService.ts`、デモ画面 `/ai-demo`）
   - `parseImage(image: File | Blob): Promise<ExtractedPriceData[]>` を定義
   - 現段階では実際のVision LLM APIを呼ばず、2秒後にダミー結果を返すモック実装
   - 将来的に `fetch` で OpenAI API 等の画像解析エンドポイントに差し替える想定（TODOコメントに記載）

5. **カード画像・公式サイトへの導線・更新日の表示**
   - 一覧・詳細・地図ポップアップの全画面でカード画像を表示（`Card.imageUrl`）。カードラッシュ／ドラゴンスターの
     商品ページに掲載されている実画像を参照している（ホットリンク。本番では利用規約を確認のうえ、
     許諾を得た画像を自社配信することを推奨）
   - 同じ型番でもパラレル・SP・イラスト違いで価格が大きく変わるため、`PriceData.printNote` に注記を持たせられる
     ようにした（例: シャンクスのillust:otton版とillust:DAI-XT.版で¥10,000と¥100の差）
   - 各価格の横に「更新日」を表示（`formatUpdatedAt`）
   - 実データが確認できた価格には「公式サイトはこちら」リンクを表示し、掲載元ページ（`PriceData.sourceUrl`）
     または店舗の公式サイト（`Shop.websiteUrl`）に遷移できるようにした。架空のデモ店舗にはリンクを出さず、
     実店舗と演出用データが一目で区別できるようにしている
   - 全画面に「価格は目安です。最終判断は各店舗の公式サイトでご確認ください」という注意書きを常時表示

6. **メルカリへの導線**（`src/config/mercari.ts`）
   - 各カードに「メルカリの相場を見る」リンクを設置（一覧の各行・詳細画面）。`mercariSearchUrl()` が
     カード名+型番でのメルカリ検索結果ページURLを組み立てる
   - メルカリは利用規約上スクレイピングでの相場取得はリスクが高く、公開APIも自社ショップ管理用の
     「メルカリShops API」のみで他者の出品検索には使えないため、今回は組み込んでいない
   - アフィリエイト（提携ASP「アクセストレード」経由）は提携審査が必要で、この場ではアカウント登録・審査を
     代行できないため、現状は素の検索リンクのみ。審査が通りアフィリエイトIDを取得したら、
     `mercariSearchUrl()` の中身を1箇所差し替えるだけでトラッキングリンクに移行できる設計にしている

## 今後のロードマップ（未実装／要検討）

実際にサービスとして成立させるには、以下の要素が別途必要です。

### 1. カードマスタの正式データ化・完全網羅への道筋
- ONE PIECEカードゲーム公式サイト（onepiece-cardgame.com/cardlist）は、ブラウザ相当のUser-Agentを
  付けたHTTPクライアントで取得すると、カード名・型番・レアリティ・公式カード画像URLがHTMLに直接
  埋め込まれていることを確認済み。当初はJS描画だと思い込んでいたが、実際にはサーバー側でレンダリング
  されていた。トップページの `<select>` から全62シリーズ（ブースター・スタートデッキ・エクストラ
  ブースター等すべて）のIDを取得でき、`scripts/fetch-onepiece-cards.mjs` はこれを総当たりして
  **公式カード2,823種**（プロモ・パラレルを含む収録カード全種）を取得している
- ただし公式サイトには**買取価格が無い**。価格が無いカードは比較のしようがないため、このアプリでは
  「公式データ」と「実店舗の買取価格データ」の両方が型番で一致したカードだけを採用している。
  現状は2店舗（メルカード2,864件・遊々亭の買取ページ全59セット走査で1,359件）の買取価格表と突き合わせて
  3,129種（うちパラレル/SP等の印刷違いが2,517種）を収録している
- パラレル版等の表記は店舗ごとに書式が異なる（メルカードは型番の前後に説明文、遊々亭はカード名末尾の
  括弧書き）ため、`parseMercardModelField()` / `parseYuyuteiVariant()` がそれぞれの書式から
  基本型番と印刷違いの注記（`variantLabel`）を分離抽出する。通常版（注記なし）は型番だけで店舗横断に
  同一カードとして突き合わせて価格比較できるが、パラレル版等は店舗表記のズレによる誤突合を避けるため
  店舗ごとに別カードのまま保持している（現状、複数店舗で価格比較できるのは271種）
- **したがって「全カードを網羅する」ことの実質的なボトルネックは公式データではなく、
  買取価格データの充実度**。完全網羅（2,823種すべてに価格を付ける）を目指すなら:
  1. 買取価格ページを持つ実店舗をさらに増やし、`fetch-onepiece-cards.mjs` の突き合わせ対象に追加する
     （店舗ごとにHTML構造が異なるため、店舗ごとのパーサーが必要。カードラッシュ（cardrush.media）の
     ように単純なfetchに対してBot対策と思われる403を返すサイトもある点に注意。候補: フルコンプ秋葉原店・
     オタチュー秋葉原・もえたく等、他にも複数の実店舗が買取表を公開していることをWeb検索で確認済み）
  2. パラレル版等の店舗横断の突き合わせ精度を上げる（変体仮名・全角半角ゆれの正規化、画像の目視照合等）
  3. それでも買取価格が個別に付かない「まとめ買取」扱いの低額カードは、原理的に「網羅」できない
     （店舗側がそもそも個別査定していないため）
- 取得したマスタは `mockData.ts` の `cards` 配列と同じ形（id / game / cardName / modelNumber / rarity /
  imageUrl）に変換してDBへ投入する想定（詳細は「3. バックエンド・永続化」参照。件数が数千規模に
  なると、フロントエンドのJSに全件バンドルする現在の方式はバンドルサイズの観点で見直しが必要になる）

### 2. データ収集の自動化（現状: Claude Codeのセッション内Routineで1日2回の自動更新を設定済み）
- **カードショップの公式サイト（買取ページ）からの収集**: メルカード・遊々亭の2店舗で実装済み
  - どちらもブラウザ相当のUser-Agentを付けたHTTPクライアントでHTMLがそのまま取得できた。
    一方カードラッシュ（cardrush.media）は一般的なfetchツールに対してBot対策と思われる403を返した
    （ブラウザ相当のUser-Agentを付けた`curl`ではHTTP 200で取得できたため、実運用でもブラウザヘッダーを
    模したHTTPクライアント、またはヘッドレスブラウザでのアクセスが必要になる可能性が高い）
  - サイトごとにHTML構造が異なるため、店舗ごとに抽出ロジック（パーサー）が必要
    （`parseMercardPrices()` / `parseYuyuteiPrices()`）
  - 利用規約・robots.txtの確認と、節度あるアクセス頻度（現状は1日2回。`fetch-onepiece-cards.mjs`内で
    リクエストごとに300ms間隔を空けている）を徹底する
  - **教訓**: 遊々亭には「/buy/」（買取＝お店が買う）と「/sell/」（販売＝お店が売る）で別ページがあり、
    URLの見た目の語感（sell=売る）から連想して当初「/sell/」＝買取だと誤って取得してしまい、買取アプリに
    販売（小売）価格が混入する事故があった（ユーザーからの指摘で発覚し修正）。複数の買取・販売ページを
    持つサイトを新たに取り込む際は、価格の大小関係（買取<販売のはず）や、ページ自体の`og:description`・
    パンくずリストのテキストで「買取」「販売」のどちらのページかを必ず裏取りしてから実装すること
- **自動実行の仕組み**: GitHub Actions等のCIではなく、Claude Code Remoteの「Routine（スケジュール実行）」
  機能を使い、このアプリの開発を行っていたセッション環境上で1日2回（UTC 11:00・23:00 = JST 20:00・8:00）
  `fetch-onepiece-cards.mjs` を実行し、生成物に差分があれば `claude/trading-card-price-map-app-61w2rp`
  ブランチにコミット・pushしたうえで `gh-pages` ブランチに再デプロイするよう設定済み（差分が無ければ
  何もしない）。これは開発時に使ったセッション環境に依存する簡易な自動化であり、恒久的な本番運用としては
  「3. バックエンド・永続化」に記載の通りGitHub Actionsのcronワークフロー等への置き換えが望ましい
  （その場合、ワークフローファイルをデフォルトブランチ`main`に置く必要がある）
- **X（旧Twitter）検索結果から買取表画像を収集する仕組み**
  - X API（有料プラン）でのツイート検索、もしくは手動でのスクリーンショット取り込み
  - X APIの利用規約・レートリミットの確認が必須
- `ImageParserService` を実際のVision LLM API（OpenAI GPT-4o Vision、Claude等）に接続
  - 抽出精度の検証、誤認識時の手動修正UI
  - 抽出したカード名・型番は上記「1. カードマスタ」と突き合わせて正規化する

- 価格データの更新日時管理・重複排除・信頼性スコアリング（同じ店舗の価格が乱立した場合の名寄せ）

### 4. 店舗データの拡充
- 現在は東京・大阪・愛知の演出用サンプル5店舗（shop-a〜e）＋実店舗3店（カードラッシュ秋葉原0号店・
  アキバカードショップ メルカード・カードショップ 遊々亭）。都道府県フィルタのUIは実装済みなので、
  店舗データを増やすだけで全国対応が可能
- 遊々亭（shop-i）は特定商取引法に基づく表記の住所を採用しているが、同ページに「送付先とは異なる」旨の
  注記があり、実質的に宅配買取（郵送査定）中心のオンライン専門店である可能性が高い。`Shop.businessHours`
  に「宅配買取のみ（来店買取なし）」と明記して区別しているが、来店可否を示す専用フィールドは無いため、
  他にも来店不可の店舗を追加する場合は `Shop` 型に `walkInAvailable: boolean` 等を追加した方が誠実な設計になる
- 住所→緯度経度のジオコーディング（Google Geocoding API等）を組み込んだ店舗登録フロー。現状は
  国土地理院の住所検索API（無料・APIキー不要）で手動取得した値を埋め込んでいる
- 店舗の営業時間・電話番号等を店舗側が自己申告 or 公開情報から収集する仕組み
- 買取価格ページを持つ実店舗の候補（Web検索で確認済み、買取表の形式は未調査）: フルコンプ秋葉原店、
  オタチュー秋葉原、もえたく、CBトレコロ、フルアヘッド、ゴールデンホビー買取センター等

### 5. ユーザー機能
- カードのお気に入り登録・価格変動通知（プッシュ通知 or メール）
- ユーザー投稿による価格情報の補完（信頼度に応じた表示）

### 6. 非機能面
- 著作権・商標（カード画像、店舗名の扱い）への配慮
- 利用規約・免責事項（買取価格は変動する旨の明記）
- 本番デプロイ（Vercel / Netlify 等）とドメイン取得
- アクセス解析・エラーモニタリング
